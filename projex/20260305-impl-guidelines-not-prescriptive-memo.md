## Context

The `impl/` folder contains runtime and verb implementation specs (`09_runtime.md`, `10_std_verbs.md`, etc.). The user's edit signals that these documents describe *one valid approach*, not the only approach. An implementer targeting a different environment (pure async, embedded, server-side) may legitimately deviate from the patterns described — e.g., replacing the tick model with async tasks, or adapting the `WAITING_HOST` push model for a different host integration pattern.

This is directly relevant to the concurrent conversation about whether the "Async Task Model" section in `09_runtime.md` still makes sense — the right framing may be: the tick model is the documented reference pattern, other models are valid adaptations. The spec (`spec/`) remains authoritative on *what* verbs do; the impl docs describe *how* a reference runtime may implement them.

Downstream effect: when auditing impl docs for correctness, "does this match the C# runtime?" is a secondary concern — the primary concern is "does this accurately describe a valid way to implement the spec?"
